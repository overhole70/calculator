# تعليمات ربط نظام تحويل النقاط (Over Mods)

ملاحظة للمنفّذ: نفّذ فقط ما هو مكتوب هنا، حرفيًا وبالترتيب. لا تعِد كتابة أي ملف، ولا تعدّل نظام شراء المودات، ولا تغيّر أي شيء غير مذكور. إن لم تجد شيئًا مما أطلبه في الكود الموجود فتوقف واسأل ولا تخمّن.

---

## 0) الصورة العامة

```
المتصفح (الواجهة)  →  server.ts  (/api/transfer)  →  Cloudflare Worker (worker.overmods.site)
                                                          └─ transfer.js  (handleTransfer)  →  Firestore
```

- الذي ينفّذ التحويل هو الـWorker فقط. الواجهة وserver.ts لا يخصمان ولا يضيفان نقاطًا.
- ملف `transfer.js` جاهز ومكتمل ومختبر محليًا. **انسخه كما هو دون أي تعديل.** (مرفق مع هذه التعليمات).

---

## 1) Cloudflare: إضافة الملف الجديد

1. افتح Workers & Pages ← الـWorker `overmods` ← **Edit code**.
2. في قائمة الملفات (يسار المحرر) أضف ملفًا جديدًا اسمه بالضبط `transfer.js` في نفس مجلد `worker.js`، والصق فيه كامل محتوى `transfer.js`.
3. لا تضغط Deploy بعد، أكمل الخطوة 2 أولًا.

إن لم يسمح محرر Cloudflare بإضافة ملف ثانٍ، توقف ولا تدمج الملفين في ملف واحد (أسماء الدوال متشابهة وسيحدث تعارض). الحل البديل هو النشر عبر Wrangler من الكمبيوتر، وأحتاج أن يُخبَر المنفّذ أنني لم أختبر هذه الحالة (الأسرار الموجودة تبقى محفوظة، لكن تأكد أن النطاق `worker.overmods.site` ما زال مربوطًا بعد النشر).

---

## 2) Cloudflare: تعديل `worker.js` (ثلاثة تعديلات فقط)

**التعديل 1:** أضف هذا السطر **قبل** السطر `const CONFIG = {` مباشرة:

```js
import { handleTransfer } from "./transfer.js";
```

**التعديل 2:** داخل `CONFIG`، أضف سطرًا جديدًا بعد السطر الذي فيه `PURCHASE_PATHS`:

```js
  PURCHASE_PATHS: ["/purchase", "/api/purchase"],
  TRANSFER_PATHS: ["/transfer", "/api/transfer"],
```

**التعديل 3:** في دالة `fetch` داخل `export default`، ابحث عن هذا السطر:

```js
      if (!CONFIG.PURCHASE_PATHS.includes(path)) {
```

وأضف **قبله مباشرة** هذه الأسطر:

```js
      if (CONFIG.TRANSFER_PATHS.includes(path)) {
        return await handleTransfer(request, env, cors);
      }
```

ثم اضغط **Deploy**.

هذا كل شيء. مسارات الشراء تبقى كما هي. التعديل مختبر محليًا: `OPTIONS` يرجع 204 مع CORS، والمسارات الأخرى لم تتأثر.

---

## 3) server.ts

لم أرَ `server.ts`، لذا افعل التالي بناءً على ما هو موجود فيه:

- ابحث عن الكود الذي يستقبل `/api/purchase` ويحوّله إلى الـWorker، وأضف بجانبه مسارًا جديدًا `POST /api/transfer` **بنفس الأسلوب تمامًا**.
- المسار الجديد يحوّل الطلب إلى `https://worker.overmods.site/transfer`.
- يجب أن يمرّر:
  - ترويسة `Authorization` كما وصلت، دون تغيير.
  - جسم JSON كما وصل بدون تعديل (`recipientNumericId` و`amount` و`requestId`).
  - `Content-Type: application/json`.
- يعيد للمتصفح **كود الحالة وجسم JSON كما أرجعهما الـWorker** (لا تحوّل 402 أو 409 إلى 200 أو 500).
- لا يخصم ولا يضيف نقاطًا ولا يقرأ الرصيد، ولا يغيّر الجسم.

---

## 4) الواجهة (صفحة "إرسال نقاط OMP")

عند ضغط "تأكيد الإرسال":

1. ولّد `requestId` **مرة واحدة لكل عملية** وخزّنه (مثلًا في متغير) واستخدم القيمة نفسها إن أعدت المحاولة بسبب انقطاع الشبكة. تتولّد قيمة جديدة فقط عندما يبدأ المستخدم تحويلًا جديدًا (بعد نجاح أو عند تغيير المستلم أو المبلغ).
2. عطّل الزر أثناء الإرسال لمنع الضغط المتكرر.
3. احصل على التوكن: `await auth.currentUser.getIdToken()` (حسب كود Firebase في مشروعك).
4. أرسل:

```js
const res = await fetch("/api/transfer", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer " + idToken,
  },
  body: JSON.stringify({
    recipientNumericId: recipientId, // نص من 10 أرقام
    amount: Number(amount),          // رقم وليس نصًا، حتى خانتين عشريتين
    requestId,                       // نفس القيمة عند إعادة المحاولة
  }),
});
const data = await res.json();
```

5. عند النجاح (`data.ok === true`): اعرض رسالة نجاح، وحدّث الرصيد المعروض بـ`data.senderBalanceAfter`، وأفرغ الحقول وولّد `requestId` جديدًا للتحويل التالي. إن كانت `data.duplicate === true` فالتحويل تم سابقًا ولم يُخصم شيء جديد، فاعرض نفس رسالة النجاح.
6. عند الفشل (`data.ok === false`) اعرض رسالة بحسب `data.code`:

| code | HTTP | الرسالة المقترحة |
|---|---|---|
| `INVALID_AMOUNT` | 400 | المبلغ غير صالح (أكثر من 0.01، وبحد أقصى خانتين عشريتين) |
| `INVALID_RECIPIENT_ID` | 400 | معرّف المستلم يجب أن يكون 10 أرقام |
| `RECIPIENT_NOT_FOUND` | 404 | المستلم غير موجود |
| `SELF_TRANSFER` | 400 | لا يمكنك التحويل لنفسك |
| `INSUFFICIENT_BALANCE` | 402 | رصيدك غير كافٍ |
| `UNAUTHORIZED` | 401 | انتهت الجلسة، سجّل الدخول من جديد |
| `CONFLICT_RETRY` أو `UPSTREAM_UNAVAILABLE` | 409 أو 503 | حدث ضغط مؤقت، أعد المحاولة (بنفس `requestId`) |
| `REQUEST_ID_CONFLICT` | 409 | خطأ في الطلب، ابدأ تحويلًا جديدًا |
| أي رمز آخر | أي | تعذر إتمام التحويل، حاول لاحقًا |

7. لا تحسب الرصيد في الواجهة ولا تخصم منه محليًا. الرصيد المعروض يؤخذ من الخادم فقط.

---

## 5) اختبار بعد النشر (حسابان تجريبيان فقط)

استخدم حسابين: أ (مرسل) وب (مستلم)، واكتب رصيد `wallet.earned` لكل منهما قبل البدء.

1. حوّل 5 نقاط من أ إلى ب بـ`numericId` الخاص بـب: يجب أن يزيد رصيد ب 5، وينقص رصيد أ 5، ويظهر سجل واحد جديد في `transactions` فيه خمسة حقول فقط (`amount` و`recipientId` و`senderId` و`timestamp` و`type`)، و`wallet.gift` لا يتغير عند أحد.
2. أعد الطلب نفسه بنفس `requestId` (من curl مثلًا): يرجع نجاحًا مع `duplicate:true`، ولا يتغير أي رصيد، ولا يظهر سجل ثانٍ.
3. حوّل أكثر من الرصيد: 402 `INSUFFICIENT_BALANCE`، ولا تغيير.
4. حوّل لمعرّف أ نفسه: 400 `SELF_TRANSFER`.
5. معرّف غير موجود (`9999999999`): 404 `RECIPIENT_NOT_FOUND`.
6. بدون توكن: 401.
7. تحقق أن شراء المودات ما زال يعمل.

---

## 6) ممنوعات

- لا تغيّر ملف `transfer.js` ولا منطق التحقق من الرصيد أو التوكن.
- لا تضع أسرارًا (مفاتيح Firebase) في server.ts أو الواجهة.
- لا تخصم أو تضف نقاطًا من أي مكان غير الـWorker.
- لا تجعل الواجهة ترسل `uid` أو الرصيد (الـWorker يتجاهلهما أصلًا).
- لا تعدّل قواعد Firestore بدون مراجعة (يجب ألا يستطيع العميل الكتابة على `transactions` ولا تعديل `wallet`).
